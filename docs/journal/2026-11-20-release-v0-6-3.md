# 2026-11-20 — Release v0.6.3

## Request

Cut v0.6.3 so that the fix of the Pod's UID reaching the model, on `main` since 2026-11-19, is in
a release, as [Maintain the repository](../how-to/maintain.md) ("Cut a release") describes.

## What was done

- Since v0.6.2, on `main`:
  - [#119](https://github.com/fedeam/kausa/pull/119): `R012` redacts UUIDs. The kubelet writes
    the Pod's UID into the back-off message of a waiting container and into the note of its
    `BackOff` event, and it reached the model in clear.
  - [#114](https://github.com/fedeam/kausa/pull/114): a watch that the API server ends with an
    error lists again instead of asking for the same resource version until it expires. On k3s
    the Event watch stalled that way for up to 6 minutes at a time.
  - [#113](https://github.com/fedeam/kausa/pull/113): `/metrics`, `/healthz` and `/readyz` read
    the whole request line before answering, so a `GET` that arrives in pieces no longer gets a
    `405`.
  - [#107](https://github.com/fedeam/kausa/pull/107): a watch error whose text changes no longer
    loses the folded repeats of the previous text.
  - Tests and CI: [#101](https://github.com/fedeam/kausa/pull/101) and
    [#104](https://github.com/fedeam/kausa/pull/104) (timing tests ended by a held call),
    [#105](https://github.com/fedeam/kausa/pull/105) and
    [#106](https://github.com/fedeam/kausa/pull/106) (the arm64 CI on Gitea), and
    [#112](https://github.com/fedeam/kausa/pull/112) (the soak sampler on macOS).
  - Docs: [#115](https://github.com/fedeam/kausa/pull/115),
    [#116](https://github.com/fedeam/kausa/pull/116) and
    [#120](https://github.com/fedeam/kausa/pull/120) (0026 and 0027), and
    [#118](https://github.com/fedeam/kausa/pull/118) (the README names the release of the Lease
    hint fix). Nothing of 0026 or 0027 is implemented in this release.
- Version 0.6.3 in `Cargo.toml`, `Cargo.lock` and the chart, with the changelog's Unreleased
  entries under `[0.6.3] - 2026-11-20`. The README, `SECURITY.md`, the front page, the command-line
  reference and the install guide name v0.6.3, and [Data sent to the
  provider](../reference/data-sent-to-the-provider.md) says the UUIDs are redacted since v0.6.3.
  Nothing to change in values or permissions.
